# Partition B: normative/source adjudication

Scope: RTM-01301 through RTM-02500 inclusive, 1,200 distinct source-row IDs. No runtime implementation or production gate is accepted by this review.

The raw candidate set contains 271 selected line fragments from five complete JSON Schemas, 743 Markdown headings and 186 other candidate occurrences. After exact text deduplication, 104 distinct operative/table/status texts required explicit semantic assignments. The assignments are stored explicitly in `part_b_build.py`; they are not inferred by term frequency or similarity scores.

The policy-decision, principal, repair-proposal, state-record and tenant contracts were read as whole objects. Their source bytes match their corresponding canonical v0.99.6 contracts. Each selected node is retained in the complete parent schema context. In particular: a principal record is not a grant; an immutable `require_approval` result cannot be edited into `permit`; repair bounds and rollout objects are strict, and executable/high-risk repair states require policy/approval bindings; state authority and projection status are distinct; tenant lifecycle/isolation/residency are actual contract fields. The current prototype does not demonstrate all these behaviors.

Each Markdown heading is a structural candidate, not by itself a behavioral assertion. Its whole source section is preserved by range and digest in 447 unique section dossiers. Section obligations remain open. `NON_NORMATIVE` on a heading or historical checked-status line must never be transferred to its surrounding behavioral requirements or treated as an implementation pass. Old schema audits and test-count claims remain historical scope evidence, not runtime acceptance.

The 104 exact-text semantic judgments preserve the following obligations: outbox/inbox atomicity, duplicate suppression, criterion-specific goal verification, source-backed Anima changes without authority, separate transport and semantic contracts, current authorizer/approver binding, cross-store deletion/redaction, projection freshness and authority isolation, unknown-outcome reconciliation, fencing at the protected adapter, independently authorized compensation, explicit schema negotiation/migrations, archival/governance separation, bounded HAL repair with rollback, immutable claim/provenance/conflict history, and source-scoped KB curation.

Supersession is narrow: old unchecked choices are resolved by the canonical decision register; the legacy claim evidence-or-exception alternative is replaced by `verified` requiring passing named verification and a verification reference; historical proposed/unreconciled specification status is replaced for the archived Phase-0 baseline by the later canonical record. Present implementation/production approval remains separate, and no human signature is asserted.

Results: 378 RETAIN, 787 NON_NORMATIVE, 35 SUPERSEDE. These are row-level source/version dispositions. All current retained behavioral/schema obligations still have missing implementation proof. `implementation_status=NOT_APPLICABLE` applies only to contextual row text, never to preserved section requirements. There are zero runtime or production acceptances.

Reproduction: run `python3 TRACEABILITY/NORMATIVE_REVIEW_20261025/part_b_build.py` from the repository root. It checks all source hashes/lines, canonical schema byte parity, exact row inventory, source/test anchors, and produces the JSONL, section dossiers and summary. Script exit zero means this evidence artifact was rebuilt consistently; it does not mean the runtime conforms.
